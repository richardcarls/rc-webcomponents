# rc-select

Select-only combobox backed by a native `<select>`, following the [WAI-ARIA Combobox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/).

## Usage

Wrap a native `<select>`. It stays in the page as the form value and the no-JavaScript
fallback, and its label names the enhanced trigger.

```html
<label>
  Fruit
  <rc-select placeholder="Choose fruit">
    <select name="fruit">
      <option value="">Choose fruit</option>
      <option value="apple">Apple</option>
      <option value="banana">Banana</option>
      <option value="cherry" disabled>Cherry</option>
    </select>
  </rc-select>
</label>
```

Add `multiple` to the native select for multiple selection.

## Accessibility

The trigger has `role="combobox"` and `aria-haspopup="listbox"`, and the popup is an
`rc-listbox` with `role="listbox"`. Focus stays on the trigger, which tracks the active option
with `aria-activedescendant`. The trigger takes its accessible name from the select's label or
`aria-label` unless it has a label of its own.

| Key                  | Action                                                                                                    |
| -------------------- | --------------------------------------------------------------------------------------------------------- |
| Down Arrow           | Opens the popup on the first option, or moves to the next option.                                         |
| Up Arrow             | Opens the popup on the last option, or moves to the previous option.                                      |
| Home, End            | Moves to the first or last option while the popup is open.                                                |
| Enter, Space         | Opens the popup, or selects the active option. A single select then closes; a multiple select stays open. |
| Escape               | Closes the popup.                                                                                         |
| Tab                  | Closes the popup and moves focus on.                                                                      |
| Printable characters | Moves to the first option whose label starts with the typed text; a closed single select selects it.      |

In a multiple select, Left Arrow on a closed trigger moves focus into the selected chips (Right
Arrow in right-to-left text). The same arrows move between chips, moving past the last chip
returns to the trigger, Escape returns to the trigger, and Delete, Backspace, Enter, or Space
removes the focused chip.

## Dialog popup

Set `popup-mode="dialog"` for constrained viewports. The component-managed fullscreen dialog
provides a leading close action, title, selected chips, option list, and Done action. Selection
is staged: Done updates the native select and fires one change event, while close, Escape, or an
imperative close discards the draft.

```html
<rc-select popup-mode="dialog" multiple placeholder="Choose categories">
  <select name="categories" multiple>
    <option value="quick">Quick meal</option>
    <option value="vegetarian">Vegetarian</option>
  </select>
</rc-select>
```

## Theming

The default demo mode shows the component without a package theme. Use the shared preview controls on this page to compare inherited, light, and dark color schemes or to apply the optional Material theme only inside the demo frames.

Inside a Material `rc-field`, a row of selected chips grows the field below its floated label, so
the label keeps the same offset as every other field. Add `rc-select--dense` to render 1.5rem chips that
fit on the field's single input line and keep a populated field at the standard 56px height. The
chips keep their full touch target.

```html
<rc-field>
  <label slot="label" for="categories">Categories</label>
  <rc-select class="rc-select--dense" multiple>
    <select id="categories" multiple>
      <option selected>Beef</option>
      <option selected>Cheap</option>
    </select>
  </rc-select>
</rc-field>
```

## Known Issues

### Firefox for Android: `<label>`-wrapped multiple selects (countermeasure implemented)

"Geckoview and Fennec open select dropdown on tap of parent label; other browsers do not." [Bugzilla 1475723](https://bugzilla.mozilla.org/show_bug.cgi?id=1475723)

To workaround this bug, `rc-select` force-disables the slotted `<select multiple>` and hooks into the associated form's `submit` and `formdata` events to preserve constraint validation and form data participation.

Label activation on a disabled control is a spec-defined no-op, mitigating the issue while maintaining progressive enhancement with minimal light DOM meddling.

However, there are two important caveats to this workaround:

1. **No native validation bubble.** The browser cannot render its validation UI on a hidden control, so when submit-time enforcement finds the select invalid (for example, `required` with nothing selected, or `setCustomValidity()`), the component cancels the submission, fires a cancelable `invalid` event on the select, and moves focus to the trigger. Call `preventDefault()` on the `invalid` event to supply your own error UI instead. `novalidate` forms, `formnovalidate` submitters, and `form.submit()` bypass enforcement, matching native scoping.
2. **Disabling through the select is one-way after upgrade.** _Enabling_ by removing the select's `disabled` (attribute or property) is captured: the component mirrors the intent and keeps the guard in place. But _disabling_ through the select is not captured; the guard already holds the `disabled` attribute present, so re-setting it is indistinguishable from the guard's own writes. Set `disabled` on `<rc-select>` itself to disable the control after upgrade.

## Localization

Built-in text follows the element's own `lang`, else `<html lang>`. Override it with
`messages`, or register it for every instance under `rc-select`: `options`, `selectedItems`, `remove`, `summary`, `done`, `cancel`. See
[Localization](../guide/localization).
