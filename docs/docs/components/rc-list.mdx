## Shared columns

`rc-list` owns leading, content, and trailing grid columns. Each direct
`rc-list-item` participates in them through CSS subgrid, so content stays
aligned even when leading visuals or trailing actions have different sizes.
If no visible row uses an optional slot, the corresponding column and gap
collapse across the whole list.

Mark an icon in the leading slot with `data-rc-list-leading` when the active
theme should apply its standard icon size and alignment. Other leading media
such as images, avatars, and selection controls retain their authored geometry.

```html
<rc-list aria-label="Recent recipes">
  <rc-list-item>
    <span slot="leading" data-rc-list-leading aria-hidden="true">★</span>
    Apple pie
    <span slot="trailing">42 min</span>
  </rc-list-item>
</rc-list>
```

Primary content truncates to one line with an ellipsis by default. Set
`--rc-list-item-content-white-space: normal` on a list or item for deliberate
multi-line rows.

### Adapt region placement

The shared column sizes and each item's leading, content, and trailing
placements are exposed as a coordinated CSS custom-property contract. Use
those tokens when a container query should rearrange the same regions without
changing source order, focus behavior, or semantics:

```css
.list-region {
  container-type: inline-size;
}

@container (max-width: 24rem) {
  .list-region rc-list {
    --rc-list-trailing-size: 0;
    --rc-list-trailing-gap: 0;
    --rc-list-item-grid-template-rows: auto auto;
    --rc-list-item-row-gap: 0.25rem;
    --rc-list-item-leading-grid-row: 1 / -1;
    --rc-list-item-content-grid-row: 1;
    --rc-list-item-trailing-grid-column: content-start / content-end;
    --rc-list-item-trailing-grid-row: 2;
    --rc-list-item-trailing-justify-self: start;
  }
}
```

Keep the named `leading-*`, `content-*`, and `trailing-*` column lines in
placement values. They are the stable coordination points supplied by
`rc-list`'s shared subgrid.

## Variants

`variant="standard"` is the default continuous list. `variant="segmented"`
creates a grouped set of discrete rows; themes use the item position assigned
by the list to shape first, middle, last, and only rows.

## Ordered lists

Set `ordered` when item order carries meaning, such as recipe steps. Each visible item receives
`aria-posinset` and `aria-setsize`, so assistive technology reports its position. The list
renders no counters: numbering the content shows, if any, stays in the item text. Items that
already carry authored positions, as in a virtualized slice, keep them.

```html
<rc-list ordered aria-label="Directions">
  <rc-list-item>1. Heat the oven.</rc-list-item>
  <rc-list-item>2. Mix the batter.</rc-list-item>
</rc-list>
```

## Reordering

Set `reorderable` to let people change the order. It implies `ordered`. Give each item a native
`<button data-rc-reorder-handle>`, usually in the `trailing` slot, and label it yourself. Handles
without an authored `aria-description` get a short keyboard hint, which `reorderMessages` can
replace along with every announcement.

- **Pointer:** press a handle and drag. The lifted item follows the pointer, the items it passes
  shift out of its way, and the nearest scroll container scrolls near its edges. Escape cancels.
  A press without movement stays a plain button press.
- **Keyboard:** Space or Enter picks the item up. The block-axis arrow keys, Home, and End move
  it, Space or Enter drops it, and Escape returns it to where it started. Moving focus away
  drops it. Each step is announced through a polite live region in the nearest open dialog or
  popover, else the document body.

Each committed move fires a cancelable `rc-list-reorder` event with `{ item, from, to }`. Left
alone, the list moves the item's node itself, so plain HTML needs no script. A framework that
renders the items cancels the event and reorders its own data; focus returns to the moved
item's handle even when the framework replaces the item's nodes. A pointer drag fires once on
drop. The keyboard fires on every step, and once more when a reorder is canceled.

```html
<rc-list reorderable aria-label="Photo order">
  <rc-list-item>
    Cover photo
    <button slot="trailing" type="button" data-rc-reorder-handle aria-label="Reorder cover photo">
      ⠿
    </button>
  </rc-list-item>
  <rc-list-item>
    Plated
    <button slot="trailing" type="button" data-rc-reorder-handle aria-label="Reorder plated">
      ⠿
    </button>
  </rc-list-item>
</rc-list>
```

```js
list.addEventListener('rc-list-reorder', (event) => {
  event.preventDefault();
  photos = move(photos, event.detail.from, event.detail.to);
});
```

While an item is lifted it carries `data-dragging` and the list carries `data-reordering`. Themes
style the lifted item with the `--rc-list-item-dragged-*` properties and animate the shifting
items with `--rc-list-item-reorder-duration`. Reduced motion turns that shift off.

## Expandable details

An item can carry a supporting region below its row in the `details` slot. Mark a button inside
the item, usually in the `trailing` slot, with `data-rc-list-item-toggle`. The item wires the
button's `aria-expanded` and `aria-controls`, keeps the region `hidden` while collapsed, and
fires `rc-list-item-toggle` with the requested state. Use `default-expanded` for an initial
uncontrolled state, or set `expanded` to control it; assign `undefined` to release control.

```html
<rc-list aria-label="Ingredients">
  <rc-list-item>
    3 garlic cloves, chopped
    <button slot="trailing" type="button" data-rc-list-item-toggle aria-label="Garlic details">
      i
    </button>
    <div slot="details">"garlic" is not a recognized unit of measure.</div>
  </rc-list-item>
</rc-list>
```

The region spans the text and trailing columns, so its content wraps freely even while the row
text truncates.

## Native selection

Use `selection="single"` with one direct radio per item, or
`selection="multiple"` with one direct checkbox per item. The native input is
the source of truth for checked, disabled, form, reset, and accessibility
behavior. The component mirrors native state to the row and makes the otherwise
non-interactive row surface activate its input. Independent links, buttons,
inputs, selects, and textareas keep their own behavior. Radios in a
single-selection list should share a `name`, exactly as they would without the
custom element enhancement.

```html
<rc-list variant="segmented" selection="single" aria-label="Sort recipes">
  <rc-list-item>
    <input slot="leading" type="radio" name="sort" value="recent" checked />
    Recently updated
  </rc-list-item>
  <rc-list-item>
    <input slot="leading" type="radio" name="sort" value="title" />
    Recipe title
  </rc-list-item>
</rc-list>
```

Programmatic writes to `selected`, `disabled`, and `interactive` are silent.
In a selecting list, the next native `change` synchronizes those presentation
states from the input again.

## Action targets

For a row whose primary action is an anchor or button rather than its selection
input, set `interactive` and point `action-target` at that same-root native
control. A plain primary click on otherwise non-interactive row content invokes
the target. Nested links, buttons, form controls, editable content, and
modifier-qualified or non-primary clicks retain their own behavior.

```html
<rc-list aria-label="Theme settings">
  <rc-list-item interactive action-target="open-theme">
    <span slot="leading" aria-hidden="true">◐</span>
    Theme
    <button id="open-theme" type="button" slot="trailing">Choose</button>
  </rc-list-item>
</rc-list>
```

The target remains its own keyboard tab stop. Delegation extends pointer reach
without creating a second interactive role on the row.

## Scope

The package intentionally does not implement drag-and-drop between lists,
swipe-to-reveal actions, virtualization, infinite loading, or pull-to-refresh.
Those behaviors have distinct data, focus, scrolling, and platform contracts
and can compose with list rows when their APIs are defined.

To render only part of a long list, wrap it in `rc-virtual-scroller` and give
each rendered row `aria-posinset` and `aria-setsize` for its place in the whole set. The list
then gives first- and last-row styling only to the set's real first and last
rows, not to the ends of the rendered slice.
