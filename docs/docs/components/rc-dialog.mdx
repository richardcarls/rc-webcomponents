# rc-dialog

Draggable, resizable wrapper for a native `<dialog>`, following the [WAI-ARIA Dialog Modal pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/).

## Usage

Place a native `<dialog>` as the direct child and name it with `aria-labelledby` or
`aria-label`. Open and close it through the `rc-dialog` element.

```html
<rc-dialog id="my-dialog">
  <dialog aria-labelledby="dlg-title">
    <h2 id="dlg-title">Hello</h2>
    <p>Dialog content.</p>
    <button type="button" onclick="document.querySelector('#my-dialog').close()">Close</button>
  </dialog>
</rc-dialog>
<button type="button" onclick="document.querySelector('#my-dialog').showModal()">Open</button>
```

## Fullscreen variant

Use `variant="fullscreen"` for a surface that follows the current visual viewport, including
browser zoom offsets and software-keyboard resizing. Move and resize behavior is disabled for
this variant. The consumer continues to author the native dialog content and accessible close
action.

```html
<rc-dialog variant="fullscreen">
  <dialog aria-labelledby="picker-title">
    <header>
      <button aria-label="Close">✕</button>
      <h2 id="picker-title">Choose categories</h2>
      <button>Done</button>
    </header>
  </dialog>
</rc-dialog>
```

## Side sheet variant

Use `variant="side"` for a modal side sheet: the surface docks to the inline end at full block
size, pads every edge for the physical safe-area insets, and rounds only its start corners. Move
and resize behavior is disabled for this variant, as for fullscreen. A theme sets its inline
size, background, start-corner radius, and shadow through `--rc-dialog-side-inline-size`,
`--rc-dialog-side-background`, `--rc-dialog-side-radius`, and `--rc-dialog-side-shadow`.

```html
<rc-dialog variant="side" closed-by="any">
  <dialog aria-labelledby="filters-title">
    <h2 id="filters-title">Filters</h2>
    <form method="dialog"><button value="apply">Apply</button></form>
  </dialog>
</rc-dialog>
```

## Accessibility

`rc-dialog` relies on the native `<dialog>`:

- `showModal()` traps Tab and Shift+Tab inside the dialog and implies `aria-modal="true"`.
- The element captures the focused element before opening and restores focus to it on close,
  falling back to `document.body` if that element was removed.
- Escape closes the dialog through `rc-dialog-request-close`, so close guards still apply.
- The dialog needs `aria-labelledby` or `aria-label`; development builds warn when both are
  missing. With `role="alertdialog"`, also point `aria-describedby` at the message.

See the [WAI-ARIA Dialog (Modal) pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/).

## Theming

The default demo mode shows the component without a package theme. Use the shared preview controls on this page to compare inherited, light, and dark color schemes or to apply the optional Material theme only inside the demo frames.

Set `--rc-dialog-min-inline-size`, `--rc-dialog-max-inline-size`, and
`--rc-dialog-max-block-size` on `<rc-dialog>` or a theme scope to bound the
standard surface. The Material theme supplies its viewport-clamped 280px to
560px dialog width. The surface fits its content inside those bounds; set
`--rc-dialog-inline-size: 100%` for a dialog whose fluid content would
otherwise shrink it to its minimum. `--rc-dialog-scrim` customizes the modal
backdrop.
