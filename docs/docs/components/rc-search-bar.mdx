## Usage

Wrap a native `<input type="search">` and label it. Wrap the bar in `<search>` when it is the
page's search landmark.

```html
<search>
  <label for="q" class="visually-hidden">Search recipes</label>
  <rc-search-bar placeholder="Search 51 recipes">
    <span slot="leading" aria-hidden="true">🔍</span>
    <input type="search" id="q" name="q" />
  </rc-search-bar>
</search>
```

## Accessibility

The component writes no ARIA to the input: `type="search"` already exposes the `searchbox` role,
and author labels are never overwritten. It adds no landmark of its own. The clear button is a
real `<button>` named by the translatable `clear` message, and activating it returns
focus to the input before the button hides. In a search view (`variant="view"`), Escape in the
input closes the open view.

## Search view

Set `variant="view"` to enable the expandable search view. The component keeps
the direct child `<input type="search">` as the value, label, and form source of
truth, while `open` / `default-open` control the view panel.

Use the `suggestions` slot for rich Material-style rows. For simple text
suggestions, the component can read the native input's `list` attribute and
render the associated `<datalist><option>` values when the slot is empty.
`<datalist>` remains a progressive enhancement path: browser styling,
high-contrast behavior, and screen-reader announcement vary, so slotted
suggestions are recommended when you need rich rows or tighter accessibility
control.

```html
<rc-search-bar variant="view">
  <input type="search" aria-label="Search recipes" list="recipe-suggestions" />
  <datalist id="recipe-suggestions">
    <option value="pasta" label="Pasta"></option>
    <option value="tomato soup"></option>
  </datalist>
</rc-search-bar>
```

## Localization

Built-in text follows the element's own `lang`, else `<html lang>`. Override it with
`messages`, or register it for every instance under `rc-search-bar`: `clear`. See
[Localization](../guide/localization).
