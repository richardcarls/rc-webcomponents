## Usage

Place a native `<textarea>` as the direct child. It is hidden after upgrade and keeps the form
value, name, and validation; its label names the editor.

```html
<label for="message">Message</label>

<rc-textarea line-numbers word-wrap auto-grow>
  <textarea id="message" name="message" rows="10" placeholder="Start typing..."></textarea>
</rc-textarea>
```

## Options

### Attributes

| Attribute        | Property        | Description                                                                               |
| ---------------- | --------------- | ----------------------------------------------------------------------------------------- |
| `line-numbers`   | `lineNumbers`   | Show sequential line numbers in the gutter.                                               |
| `gutter`         | `gutter`        | Show an empty gutter that plugins can populate with `LineDecoration.gutterContent`.       |
| `word-wrap`      | `wordWrap`      | Wrap long lines instead of scrolling horizontally.                                        |
| `auto-grow`      | `autoGrow`      | Let the field grow vertically with content.                                               |
| `line-direction` | `lineDirection` | `base` (default) gives every line the editor's direction; `auto` gives each line its own. |

Read-only state comes from the slotted native control: set `readonly` on the `<textarea>`. The
editor keeps the enabled field appearance, stays focusable and selectable, announces
`aria-readonly`, and rejects edits. The host matches `:state(readonly)`, and the `readOnly`
getter reports the state.

Use a plugin with `LineDecoration.gutterContent` for sparse numbering. Put accessible names on
the slotted textarea with `aria-label` or a real `<label for="...">`.

### Content language and direction

The slotted `<textarea>` describes the content, and the host describes the interface. Put the
text's language and direction on the textarea, as on any form control:

- **`lang`** is mirrored onto the editor, so the browser picks the right glyphs (Han characters
  differ between `ja` and `zh`), spelling dictionary and hyphenation. Plugins read it as
  `contentLang`, and `getWordAtCursor()` segments words for it.
- **`dir`** sets the editor's base direction. `ltr` and `rtl` are used as written. `auto` takes
  the direction of the value's first strong character and uses LTR when there is none,
  as a native textarea does, and updates as the value changes. Without `dir` the editor
  inherits. `dirname` submits the resolved direction with the form, since the native control
  always holds the value.
- **`spellcheck`** is mirrored when the textarea sets it. Without it, spelling checks stay off.

Changing the textarea's `lang` or `dir` also reruns plugin rendering, so highlighting and
decorations can follow the new content language or direction.

The host's own `lang` is the interface language, as for every `rc-*` component. It formats line
numbers, so an `ar-EG` interface shows `١ ٢ ٣`, and `ar-EG-u-nu-latn` keeps Latin digits. The
gutter, fold controls and line-action popover follow the host's direction, not the content's.

`line-direction="auto"` suits prose that mixes scripts, such as an Arabic recipe with an
English brand name on one line. Each line with a letter orders and aligns by its own first
strong character (`unicode-bidi: plaintext`). Lines without one, such as an empty line or a
quantity, keep the base direction, so the caret on a new line in an Arabic recipe starts on the
right. Type U+200E or U+200F at the start of a line to force its direction. Leave it at `base`
for code. Widgets are isolated, so they never reorder the text around them or set a line's
direction.

### JavaScript properties

| Property                          | Type                       | Description                                                           |
| --------------------------------- | -------------------------- | --------------------------------------------------------------------- |
| `value`                           | `string`                   | Current plain-text value. Host writes are silent.                     |
| `defaultValue`                    | `string \| undefined`      | Initial uncontrolled value.                                           |
| `plugin`                          | `RCTextareaPlugin \| null` | Declarative plugin hook for reactive frameworks.                      |
| `lineDirection`                   | `'auto' \| 'base'`         | How each line's direction is chosen; reflects `line-direction`.       |
| `decorations`                     | `DecorationInput[]`        | External decoration layer merged with plugin and pattern decorations. |
| `selectionStart` / `selectionEnd` | `number`                   | Current plain-text selection offsets (read-only).                     |

## Events

All events bubble and are composed.

| Event                | Detail                                             | Fires when                                         |
| -------------------- | -------------------------------------------------- | -------------------------------------------------- |
| `rc-textarea-change` | `{ value: string }`                                | User editing changes the plain-text value.         |
| `rc-textarea-focus`  | none                                               | The editor receives focus.                         |
| `rc-textarea-blur`   | none                                               | The editor loses focus.                            |
| `rc-textarea-select` | `{ selectionStart: number, selectionEnd: number }` | The selection changes while the editor is focused. |

```ts
editor.addEventListener('rc-textarea-change', (e) => {
  console.log(e.detail.value);
});
```

## Accessibility

The editor is a `role="textbox"` with `aria-multiline="true"`. It takes its accessible name from
the native textarea's `aria-label`, else the text of the textarea's labels.

| Key                               | Behavior                                                    |
| --------------------------------- | ----------------------------------------------------------- |
| `Tab`                             | Inserts `\t`.                                               |
| `Escape`, then `Tab`              | Moves focus to the next element instead of inserting a tab. |
| `Shift+Tab`                       | Moves focus to the previous element.                        |
| `Ctrl/Cmd+Z`                      | Undo.                                                       |
| `Ctrl/Cmd+Y` / `Ctrl/Cmd+Shift+Z` | Redo.                                                       |
| `Paste`                           | Inserts plain text only; normalizes line endings.           |
| `Enter`                           | Inserts a line break.                                       |

While the editor contains an accessible widget, such as an expanded folding panel, `Tab` moves
focus instead of inserting a tab, so the widget stays reachable.

## Theming

`rc-textarea` is design-system neutral and uses CSS system colors by default.

### Component tokens

| Token                                     | Default                               | Use                                                                                                                      |
| ----------------------------------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `--rc-textarea-font-family`               | `monospace`                           | Editor and gutter font family. While unset, the editor copies the native `<textarea>`'s font, line height, and spacing.  |
| `--rc-textarea-font-size`                 | `1em`                                 | Editor and gutter font size.                                                                                             |
| `--rc-textarea-line-height`               | `1.5`                                 | Editor and gutter line height.                                                                                           |
| `--rc-textarea-padding-block`             | `0.5em`                               | Editor and gutter block padding; any `padding-block` value.                                                              |
| `--rc-textarea-padding-inline`            | `0.5em`                               | Editor inline padding (both sides) and gutter start padding; one length, which the active line highlight bleeds through. |
| `--rc-textarea-gutter-min-inline-size`    | `24px`                                | Minimum gutter width including padding; Material uses `48px`.                                                            |
| `--rc-textarea-background`                | `Field`                               | Field background.                                                                                                        |
| `--rc-textarea-color`                     | `var(--rc-field-text, FieldText)`     | Field text color.                                                                                                        |
| `--rc-textarea-caret-color`               | `var(--rc-textarea-color, FieldText)` | Caret color.                                                                                                             |
| `--rc-textarea-border`                    | `1px solid ButtonBorder`              | Field border.                                                                                                            |
| `--rc-textarea-border-radius`             | `2px`                                 | Field corner radius.                                                                                                     |
| `--rc-textarea-focus-outline`             | `2px solid Highlight`                 | Focus ring.                                                                                                              |
| `--rc-textarea-active-line-bg`            | `transparent`                         | Full-width active line highlight.                                                                                        |
| `--rc-textarea-gutter-bg`                 | `Canvas`                              | Gutter background.                                                                                                       |
| `--rc-textarea-gutter-color`              | `GrayText`                            | Gutter text color.                                                                                                       |
| `--rc-textarea-gutter-border`             | `1px solid ButtonBorder`              | Gutter separator.                                                                                                        |
| `--rc-textarea-gutter-padding-inline-end` | `0.75em`                              | Space between gutter labels and text.                                                                                    |

Plugin-provided line actions expose the `--rc-line-actions-*` and
`--rc-line-action-*` hooks listed in the generated API table. Inline actions
inherit the editor surface by default; popover actions use system-color
surface defaults where they need independent chrome.

```css
rc-textarea {
  color-scheme: dark;
  --rc-textarea-font-family: 'Fira Code', monospace;
  --rc-textarea-font-size: 13px;
  --rc-textarea-background: #1e1e2e;
  --rc-textarea-color: #cdd6f4;
  --rc-textarea-active-line-bg: rgb(255 255 255 / 0.06);
}
```

### CSS parts

The exposed CSS parts are `root`, `gutter`, `gutter-cells`, `editor-area`, `editor`,
`fold-trigger`, and `fold-icon`. The last two exist when a folding action is rendered;
`fold-icon` exists only when its plugin supplies an icon.

```css
rc-textarea::part(editor) {
  tab-size: 2;
}

rc-textarea::part(fold-trigger) {
  border-radius: 0.25em;
  color: CanvasText;
}
```

### Decoration styles

Decoration elements (`.mark`, `.line`, `.widget`) live inside the shadow root. Use
`api.adoptStyleSheet()` from a plugin to reach them; document stylesheets cannot pierce the
shadow boundary.

## Pattern Highlights

Use `addPattern()` for lightweight regex decoration without writing a plugin.

```ts
const todoId = editor.addPattern({
  pattern: /\bTODO\b/g,
  bold: true,
  color: 'var(--editor-todo-color)',
});

editor.removePattern(todoId);
editor.clearPatterns();
```

Patterns can also style named capture groups and add line diagnostics:

```ts
editor.addPattern({
  pattern: /^(?<key>\w[\w-]*):\s*(?<value>.+)$/gm,
  captureGroups: {
    key: { bold: true, color: 'var(--editor-key-color)' },
    value: { color: 'var(--editor-value-color)' },
  },
  createLineDecoration: () => ({ className: 'config-line' }),
});
```

## Folding actions

Import `FoldingActionController` from `@rcarls/rc-textarea/folding` or
`@rcarls/rc-webcomponents/rc-textarea/folding` when using the aggregate package.

`FoldingActionController` creates independent native buttons with `aria-expanded`.
Give each action a stable key, a contextual label, and a target: an app-owned panel
element or `{ fromLine, toLine }` for inclusive, one-based source lines after its
anchor. Source folds start expanded; set `initiallyExpanded: false` for diagnostic
panels. The controller manages panel visibility and focus return; plugins create
panel content as an accessible block widget and version its widget key when content
changes. `clear()` resets folding state when document identity changes or the plugin
is destroyed. A Markdown plugin can supply parser-backed ranges without teaching
the editor Markdown grammar.

Supply an icon with the controller's `createTriggerIcon(expanded)` option. The
icon is decorative and receives the `fold-icon` CSS part. The built-in Markdown
plugin forwards the same option through its factory:

```ts
const plugin = createMarkdownPlugin({
  folding: {
    createTriggerIcon(expanded) {
      const icon = document.createElement('span');
      icon.textContent = expanded ? '▾' : '▸';
      return icon;
    },
  },
});
```

Use `::part(fold-trigger)` and `::part(fold-icon)` from consumer CSS to style the
control and icon. Keep focus visibility and the button's hit area intact.

`gutterLine` places a control in the gutter; a trailing `offset` uses the reserved
lane sized by `--rc-textarea-trailing-size`. `createGutterContent(button)` and
`updateGutterContent(wrapper)` add and refresh a decorative status marker. The
gutter has a 24px minimum width in the base component and 48px in Material.
Each row follows its text line height, so an inline folding control can be shorter
than 24px under [WCAG 2.5.8's line-height exception](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum).
The full gutter cell is the hit area for a single action; multiple actions share
the cell without overlapping targets. Enter and Space activate the native button.
Folding never changes the field value or undo history.
