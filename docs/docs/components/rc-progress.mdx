# rc-progress

Native `<progress>` enhancer with a formatted value display, a restylable track/fill, and a

## Usage

Wrap a native `<progress>`, and name it with a `<label for>` or `aria-label`; the component
renders no label of its own. Both forms work before JavaScript loads.

```html
<label for="sync">Sync</label>
<rc-progress>
  <progress id="sync" max="100" value="40"></progress>
</rc-progress>
```

## Accessibility

The native `<progress>` keeps its `progressbar` role and value, so assistive technology reads the
same progress before and after upgrade. The component forwards `value-text` to `aria-valuetext`
and `orientation="vertical"` to `aria-orientation`. Its track, fill, and formatted value display
are decorative. The bar takes no focus and has no keyboard interaction.

## Determinate vs. indeterminate

Binding `undefined` to a live `<progress>.value` throws. Toggle the `indeterminate`
attribute instead: the component removes and restores the native element's `value`
attribute for you, so you never have to reach for that binding yourself.

## Doing one job

`rc-progress` does not render a dialog, own any phase state, or assume anything about
where it's placed. It composes cleanly with `rc-dialog`, a card, or an inline status
row: bring your own chrome, and let `rc-progress` handle the bar.
