# Server templates

`rc-pagination`, `rc-breadcrumbs`, and `rc-data-table` enhance markup that a
server page already has: a `<nav>` of page links, an ordered list of links, a
table with sortable headers. A server-rendered app writes that markup once, in
a partial, and every page that uses it works with or without JavaScript. This
guide gives those partials for Rails (ERB), Laravel (Blade), and ASP.NET Core
(Razor components).

The partials follow the same rules in every framework:

- **The server owns the state.** The current page and sort order come from the
  request, and the partials write them as attributes (`page`, `sort-key`,
  `sort-direction`). The elements treat attributes the server sets as controlled
  state.
- **Every control is a link.** Paging and sorting send a new request, so the
  markup works before the elements upgrade and with scripting off. Once they
  upgrade, the elements add names, `aria-current`, and announcements, and fire
  their events before the link navigates.
- **The partial writes the accessible state too.** It sets `aria-current` and
  `aria-sort` itself, so the first paint is correct and a page update that
  morphs the DOM (Turbo, Livewire, htmx) keeps it. See
  [Pages updated by DOM morphing](./ssr#pages-updated-by-dom-morphing).

CI renders each partial on this page with ActionView, Blade, and the Razor
`HtmlRenderer`, and checks the output against the markup the components
document.

## Pagination

The partial takes the current page, the page count, a function that returns
the URL of a page, and an optional landmark name. It renders nothing for a
single page, leaves out the previous and next links at either end, and lists
the pages the way `paginationRange()` from `@rcarls/rc-pagination/range` does:
the first and last page, the pages beside the current one, and an ellipsis for
each hidden run of two or more pages. Each framework gets a port of that
function, tested against the original.

```ruby title="app/helpers/rc_helper.rb"
module RcHelper
  # The pages to list, with :ellipsis for each run of hidden pages.
  # A port of paginationRange() from @rcarls/rc-pagination/range.
  def rc_pagination_range(page, total, siblings: 1, boundaries: 1)
    last = [total.to_i, 0].max
    return [] if last.zero?

    current = page.to_i.clamp(1, last)
    shown = [
      *(1..boundaries),
      *((last - boundaries + 1)..last),
      *((current - siblings)..(current + siblings)),
    ].select { |value| value.between?(1, last) }.uniq.sort

    shown.each_with_index.flat_map do |value, index|
      gap = index.zero? ? 1 : value - shown[index - 1]

      if gap == 1
        [value]
      elsif gap == 2
        [value - 1, value]
      else
        [:ellipsis, value]
      end
    end
  end

  # The direction a sortable header link asks for: the reverse of the current
  # direction on the sorted column, else the column's first direction.
  def rc_next_sort_direction(key, sort_key, sort_direction, first: "ascending")
    return first unless key == sort_key

    sort_direction == "ascending" ? "descending" : "ascending"
  end
end
```

```php title="app/Support/Rc.php"
<?php

namespace App\Support;

final class Rc
{
    /**
     * The pages to list, with 'ellipsis' for each run of hidden pages.
     * A port of paginationRange() from @rcarls/rc-pagination/range.
     *
     * @return list<int|'ellipsis'>
     */
    public static function paginationRange(int $page, int $total, int $siblings = 1, int $boundaries = 1): array
    {
        $last = max(0, $total);

        if ($last === 0) {
            return [];
        }

        $current = min(max(1, $page), $last);
        $shown = [];

        $add = function (int $from, int $to) use (&$shown, $last): void {
            for ($value = max(1, $from); $value <= min($last, $to); $value++) {
                $shown[$value] = true;
            }
        };

        $add(1, $boundaries);
        $add($last - $boundaries + 1, $last);
        $add($current - $siblings, $current + $siblings);

        $pages = array_keys($shown);
        sort($pages);

        $items = [];
        $previous = null;

        foreach ($pages as $value) {
            if ($previous !== null && $value - $previous === 2) {
                $items[] = $previous + 1;
            } elseif ($previous !== null && $value - $previous > 2) {
                $items[] = 'ellipsis';
            }

            $items[] = $value;
            $previous = $value;
        }

        return $items;
    }

    /**
     * The direction a sortable header link asks for: the reverse of the current
     * direction on the sorted column, else the column's first direction.
     */
    public static function nextSortDirection(string $key, ?string $sortKey, string $direction, string $first = 'ascending'): string
    {
        if ($key !== $sortKey) {
            return $first;
        }

        return $direction === 'ascending' ? 'descending' : 'ascending';
    }
}
```

@code {
    [Parameter, EditorRequired] public int Page { get; set; }
    [Parameter, EditorRequired] public int Total { get; set; }
    [Parameter, EditorRequired] public Func<int, string> Href { get; set; } = default!;
    [Parameter] public string? Label { get; set; }

    /// <summary>
    /// The pages to list, with <c>null</c> for each run of hidden pages.
    /// A port of paginationRange() from @rcarls/rc-pagination/range.
    /// </summary>
    public static IReadOnlyList<int?> Range(int page, int total, int siblings = 1, int boundaries = 1)
    {
        var last = Math.Max(0, total);

        if (last == 0)
        {
            return [];
        }

        var current = Math.Clamp(page, 1, last);
        var shown = new SortedSet<int>();

        void Add(int from, int to)
        {
            for (var value = Math.Max(1, from); value <= Math.Min(last, to); value++)
            {
                shown.Add(value);
            }
        }

        Add(1, boundaries);
        Add(last - boundaries + 1, last);
        Add(current - siblings, current + siblings);

        var items = new List<int?>();
        int? previous = null;

        foreach (var value in shown)
        {
            if (previous is int before && value - before == 2)
            {
                items.Add(before + 1);
            }
            else if (previous is int start && value - start > 2)
            {
                items.Add(null);
            }

            items.Add(value);
            previous = value;
        }

        return items;
    }
}

## Breadcrumbs

The partial takes the trail as a list of label and URL pairs, ending with the
current page, which gets `aria-current="page"`. The element names the landmark
"Breadcrumb" unless you pass a name.

## Sortable tables

The server sorts the rows, so each sortable header is a link to the same page
with the other sort order. The partial renders one header cell: its
`data-rc-sort-key`, `aria-sort` when the table is sorted by that column, and a
link that asks for the next direction. That is the reverse direction on the
sorted column, and on any other column its first direction, ascending unless
`first` is `descending`. The page wraps the table in `<rc-data-table>` with the
current `sort-key` and `sort-direction`.

Read the sort key and direction from the query string through an allowlist
before they reach the database query, and fall back to the default order for
any other value:

```ruby
SORTS = { "name" => :name, "joined" => :created_at }.freeze

@sort = SORTS.key?(params[:sort]) ? params[:sort] : "name"
@direction = params[:dir] == "descending" ? "descending" : "ascending"
@members = Member.order(SORTS[@sort] => @direction == "ascending" ? :asc : :desc)
```

## After the page loads

The elements fire `rc-pagination-change` and `rc-data-table-sort` before a link
navigates. Leave the event alone and the link works as usual, including when
Turbo or `hx-boost` takes it over. To load the new rows from your own script
instead, cancel the event; that also cancels the link.
